# Запрос агенту при CAPTCHA

Hugin может отправлять один запрос в существующий местный чат Codex при новой
проверке CAPTCHA hh.ru. Агент использует GPT-6.1 Sol с высоким уровнем рассуждения.
Нужны Windows, действующий вход в настольном приложении Codex, установленная команда
`codex queue`, зарегистрированные ссылки `codex://` и доступный агенту Computer Use.

В местной `.env` задайте:

```dotenv
HUGIN_CAPTCHA_AGENT_THREAD_ID=идентификатор-существующего-чата
HUGIN_CAPTCHA_AGENT_CODEX_PATH=C:/путь/к/codex.exe
```

Идентификатор должен быть UUID существующего чата. Пустой идентификатор отключает
отправку запросов. Если путь не задан или больше не существует, используется
`codex` из PATH. После изменения настройки перезапустите обычное окно Hugin.
Параметры модели самого Hugin при этом не меняются.

Событие создаётся при сохранении новой рабочей блокировки CAPTCHA. Откат
транзакции и CAPTCHA в намеренно приостановленной работе не запускают агента.
Окно Hugin ожидает уведомления PostgreSQL, без периодического опроса состояния.
После подключения один раз проверяется уже сохранённая блокировка, чтобы не
потерять случай, возникший во время отключения окна.
Перед прохождением агент проверяет действующее разрешение пользователя по
записям текущего проекта. Если оно не подтверждено, агент запросит разрешение.

Hugin ставит запрос через `codex queue`, затем открывает существующий чат ссылкой
`codex://threads/<идентификатор>`. Приложение загружает чат и выполняет запрос со своим
доступом к браузеру. Одной очереди для неактивного чата недостаточно. Отдельный запуск
`codex exec resume` также не подходит: он может завершить ход, но не получает регистрацию
браузерного сеанса настольного приложения. Настройки безопасности при вызове не меняются.
Открытие чата может показать окно Codex; это происходит только по случаю CAPTCHA.
Агент проверяет актуальность блокировки, открывает штатную кнопку Hugin и проходит
доступную проверку в том же браузере. Для команды постановки отведено до 30 секунд.
Отметка `desktop_requested` означает постановку и открытие чата, а не завершение
агента или решение CAPTCHA. Итог подтверждается историей чата и свежими состоянием
и журналом Hugin после принятия проверки на hh.ru.
Прежний режим восстанавливает сам Hugin после проверки авторизации. Ручная пауза,
дневной лимит и защита неизвестных исходов сохраняются.

Каждая CAPTCHA получает устойчивый номер в базе. Изменение времени следующей
попытки или других полей состояния не меняет этот номер.
Один случай отмечается в местной папке данных `captcha-agent`. Повторное событие,
перезапуск окна и неопределённый результат вызова Codex не отправляют тот же
запрос заново. Номер сообщения, вывод команды и ошибки сохраняются рядом с отметкой
случая в файлах `.json`, `.stdout.txt` и `.stderr.txt`; это местные закрытые данные.
Если открыть приложение не удалось, остаётся `desktop_failed` и номер уже поставленного
сообщения. Неподтверждённый запрос требует
разбора по журналу `agent.request`:
не удаляйте его отметку для слепого повтора. Новый случай после восстановления
получает отдельный запрос.

При недоступности Codex, Computer Use, неизвестном адресе или запросе неизвестных
данных CAPTCHA остаётся защитной остановкой. Не меняйте состояние базы вручную.
Работающий компьютер и доступный агенту рабочий стол необходимы для решения.
