# Разбор смысла требований

В настройках каждого направления есть переключатель **«Разбирать смысл требований»**.
По умолчанию он выключен. При включении новый разбор заменяет прежний отбор по
профессиональным словам в этом направлении. Ограничения по доступности вакансии,
давности, месту и формату работы, неоплачиваемой работе сохраняются.

После обновления запустите Hugin обычным способом: приложение само применит изменение
структуры базы. Затем включите разбор в нужных направлениях и поиск. Анализ выполняется
отдельно от браузера; остановленный поиск не начинает новые обращения к модели.
Уже начатое обращение может закончиться после остановки. Разбор одной вакансии
расходует лимит подписки Codex; время зависит от текста и доступности модели. Пауза откликов не останавливает
анализ при включённом поиске и не выключает автоматические ответы работодателям.

## Как получается решение

1. GPT-5.6 Terra со средним уровнем рассуждения за одно обращение получает полный
   сохранённый текст вакансии и подтверждённые профессиональные факты выбранного
   резюме. Точные повторы описания в отдельных полях не передаются второй раз;
   заголовки, порядок и повторы внутри описания сохраняются.
2. Модель оценивает основную работу целиком: профессию, соответствие профилю,
   подтверждения и пробелы. Вывод содержит ссылки на исходные строки и факты.
   Ответы анкет не входят в общий профессиональный профиль.
   Формат разрешает только существующие номера строк и фактов; число ссылок
   на текст не ограничивается десятью, а на основание отказа — четырьмя.
3. Программа проверяет форму, цитаты, ссылки и согласованность ответа. Для отказа
   нужна явно обязательная основная чужая специализация с подтверждением из текста.
   Стаж и новые средства в близкой работе снижают приоритет. Содержательное сомнение
   допускает вакансию с низким приоритетом; неопределённая профессия не вызывает
   автоматический перенос в другое направление. Ошибка модели или неверный ответ
   оставляет вакансию вне очереди с пометкой **«Нужен разбор»**.

Новые средства для RAG, готовых моделей, отчётности и автотестов с обучением,
сопровождение собственного приложения Python и английский B2 при подтверждённом B1
сами по себе не запрещают отклик. Это правила допуска, а не утверждение о наличии
опыта: в письмах и ответах используются только подтверждённые сведения.
Работа с новым хранилищем в аналитике и подготовка стенда для проверки программы
оцениваются по конкретным обязанностям. Они не означают автоматически отдельную
специализацию по распределённым платформам или оборудованию. Широкий перечень
будущих задач при базовых требованиях к стажёру также не доказывает необходимость
готового опыта во всех перечисленных областях. Явно обязательная основная чужая
специализация остаётся основанием для отказа.
Подтверждённое желание развиваться в машинном обучении не снижает приоритет и
не подтверждает опыт обучения моделей. Будущее собеседование или тестовое задание
не должно быть уже пройдено, чтобы вакансия попала в профессиональный отбор.
Вакансии с пониженным приоритетом участвуют в автоматической подготовке только
при разрешённых в настройках откликах на такие вакансии.

На один проход приходится не более одного обращения к модели. Автоматического
исправления ответа дополнительными обращениями в этом проходе нет. После ошибки
повтор возможен через 30 минут; ожидание ответа ограничено пятью минутами.
Содержательное сомнение само по себе повтор не запускает.

Результат сохраняется вместе с исходными данными. При неизменных тексте, профиле,
модели и инструкциях повторного обращения нет. Изменение этих данных требует новой
общей оценки, включая изменение профиля. Перед подготовкой и отправкой программа
сверяет актуальность решения. Устаревшее решение останавливает задание; новый
допустимый результат может восстановить его, сохраняя письмо. Иные причины ручной
проверки не снимаются. Независимые ограничения ручным принятием не отменяются.

История прежнего двухэтапного разбора сохраняется и воспроизводится по его версии.
Она не заменяет результат нового алгоритма: после обновления для действующего
отбора нужна новая оценка. Начатая общая оценка сохраняет нумерацию исходных строк,
если целостность сохранённой записи подтверждена. Исходные поля не переписываются.

SQL-аналитика и создание витрин с незнакомыми Hadoop, Hive или Spark допускаются
с низким приоритетом, если основная работа не требует самостоятельной эксплуатации
кластеров. Допуск не подтверждает отсутствующий опыт: письма и ответы используют
только подтверждённые сведения.

Перенос между направлениями возможен только при включённом разборе в целевом
направлении. Если такого направления нет, подходящая вакансия остаётся в исходном.
Для другого резюме нужен собственный актуальный результат сопоставления.

## Проверка сохранённого результата

После обновления структуры базы можно прочитать решение по местному номеру вакансии:

```powershell
uv run python -m hugin.semantic_cli inspect --direction-id 1 --vacancy-id 123 --output .work/selection-123.json
```

Отдельный разбор сохранённой вакансии без действий на hh.ru и без создания очереди:

```powershell
uv run python -m hugin.semantic_cli analyze --direction-id 1 --vacancy-id 123 --output .work/selection-123-new.json
```

`analyze` обращается к моделям, сохраняет разбор в базе и пересчитывает оценку вакансии.
Команда не включает переключатель направления. Номер вакансии — внутренний номер
Hugin, а не номер из адреса hh.ru. Существующий файл не перезаписывается.
Результат содержит личные исходные тексты: храните его местно, вне репозитория.

История оценки содержит входные данные и ответы модели. Обычный повтор через
`hugin.diagnostic_cli replay` вычисляет решение по сохранённым ответам без новых
обращений к модели. Он проверяет воспроизводимость программы; правильность понимания
вакансии моделью требует отдельной проверки исходного текста.
