# Разбор смысла требований

В настройках каждого направления есть переключатель **«Разбирать смысл требований»**.
По умолчанию он выключен. При включении новый разбор заменяет прежний отбор по
профессиональным словам в этом направлении. Ограничения по доступности вакансии,
давности, месту и формату работы, неоплачиваемой работе сохраняются.

После обновления запустите Hugin обычным способом: приложение само применит изменение
структуры базы. Затем включите разбор в нужных направлениях и поиск. Анализ выполняется
отдельно от браузера; остановленный поиск не начинает новые обращения к модели.
Уже начатое обращение может закончиться после остановки. Разбор одной вакансии обычно
занимает несколько минут и расходует лимит подписки Codex. Пауза откликов не останавливает
анализ при включённом поиске и не выключает автоматические ответы работодателям.

## Как получается решение

1. GPT-5.6 Luna со средним уровнем рассуждения получает полный сохранённый текст
   вакансии, включая отдельные поля требований и навыков. Она выделяет обязанности,
   обязательные условия, пожелания, уровень знаний и явно разрешённые альтернативы.
   Профиль кандидата на этом этапе не передаётся.
2. GPT-5.6 Sol со средним уровнем рассуждения сопоставляет условия с полными
   подтверждёнными профессиональными фактами выбранного для направления резюме.
   Каждое подтверждение ссылается на факт, каждое требование — на исходную строку.
3. Программа проверяет форму и ссылки, а затем принимает решение. Неподтверждённая
   основная чужая специализация запрещает отклик. Стаж, масштаб и новые средства
   в близкой работе снижают приоритет. Сомнение в соответствии вакансии, уровне
   требования или образовании допускает отклик с пониженным приоритетом.
   Неустранённое разногласие моделей о смысле текста тоже допускает отклик;
   причина сомнения остаётся в оценке. Неопределённая профессия не вызывает
   автоматический перенос в другое направление.
   Если ответ модели не получен или содержит неверные ссылки и неполные данные,
   вакансия временно остаётся вне очереди с пометкой **«Нужен разбор»**.

Новые средства для RAG, готовых моделей, отчётности и автотестов с обучением,
сопровождение собственного приложения Python и английский B2 при подтверждённом B1
сами по себе не запрещают отклик. Это правила допуска, а не утверждение о наличии
опыта: в письмах и ответах используются только подтверждённые сведения.
Подтверждённое желание развиваться в машинном обучении не снижает приоритет и
не подтверждает опыт обучения моделей. Будущее собеседование или тестовое задание
не должно быть уже пройдено, чтобы вакансия попала в профессиональный отбор.
Вакансии с пониженным приоритетом участвуют в автоматической подготовке только
при разрешённых в настройках откликах на такие вакансии.

При ошибках программа делает ограниченные исправления: не более шести обращений
на один проход. Ошибка поставщика или неполный разбор допускает повтор через 30 минут.
Ожидание отдельного ответа ограничено пятью минутами.
Содержательная неопределённость не требует ручного решения и не запускает
бесконечные повторы. Допуск по сомнению не подтверждает отсутствующие навыки:
письма и ответы по-прежнему используют только подтверждённые сведения.

Разбор и сопоставление сохраняются отдельно. Неизменившийся текст не разбирается
заново при изменении профиля. Изменение текста, подтверждённых фактов, выбранного
резюме, модели или инструкций делает соответствующее решение устаревшим.
Перед подготовкой и отправкой программа сверяет решение с текущими данными.
Устаревшее решение останавливает задание; новый допустимый результат может
восстановить его, сохраняя письмо. Иные причины ручной проверки не снимаются.
Ручное принятие вакансии связано с текущими данными и не отменяет независимые
ограничения по условиям работы и доступности.

Перенос между направлениями возможен только при включённом разборе в целевом
направлении. Если такого направления нет, подходящая вакансия остаётся в исходном.
Для другого резюме нужен собственный актуальный результат сопоставления.

## Проверка сохранённого результата

После обновления структуры базы можно прочитать решение по местному номеру вакансии:

```powershell
uv run python -m hugin.semantic_cli inspect --direction-id 1 --vacancy-id 123 --output .work/selection-123.json
```

Отдельный разбор сохранённой вакансии без действий на hh.ru и без создания очереди:

```powershell
uv run python -m hugin.semantic_cli analyze --direction-id 1 --vacancy-id 123 --output .work/selection-123-new.json
```

`analyze` обращается к моделям, сохраняет разбор в базе и пересчитывает оценку вакансии.
Команда не включает переключатель направления. Номер вакансии — внутренний номер
Hugin, а не номер из адреса hh.ru. Существующий файл не перезаписывается.
Результат содержит личные исходные тексты: храните его местно, вне репозитория.

История оценки содержит входные данные и ответы модели. Обычный повтор через
`hugin.diagnostic_cli replay` вычисляет решение по сохранённым ответам без новых
обращений к модели. Он проверяет воспроизводимость программы; правильность понимания
вакансии моделью требует отдельной проверки исходного текста.
